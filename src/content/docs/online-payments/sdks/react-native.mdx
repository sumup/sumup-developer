The React Native Checkout SDK displays a payment sheet in your mobile app. Your server creates the checkout; the app uses a public merchant key to collect payment details and present the sheet.

This guide uses the alpha release `@sumup/react-native-checkout@0.0.0-alpha.4`. Its API can change between releases.

<Image alt="Challenge screen" src="/img/guides/react_native_payment_sheet.png" width="40%" />

## Integration

### Before You Begin

Before you start, you need:

- A [sandbox merchant account](/online-payments/#getting-a-sandbox-merchant-account) and the [online test cards](/online-payments/testing/).
- A backend that creates checkouts for your orders and keeps secret API keys or OAuth client secrets on the server. Use an [API key](/tools/authorization/api-keys/) for your own merchant or [OAuth](/tools/authorization/oauth/) when other merchants connect to your app.
- Your merchant's public key, beginning with `sup_pk_`, from [Developer Settings](https://me.sumup.com/settings/api-keys).
- A React Native app with access to its native iOS and Android projects.

<Callout type="caution" title="Keep secret credentials on your server">
Use the public merchant key in `SumUpProvider`. Never put a secret key beginning with `sup_sk_` or an OAuth client secret in your app, including build-time environment variables bundled with the app.
</Callout>

## Set up SDK

Install the published SDK and its WebView dependency:

```bash
npm install @sumup/react-native-checkout@0.0.0-alpha.4 react-native-webview
```

For iOS, install the native modules:

```bash
cd ios
pod install
```

The examples below set `language: "en"`. To detect the device language instead, install `react-native-localization` and omit `language`. The SDK supports `en` and `sv`.

Wrap your payment screen in `SumUpProvider`. Replace the public-key placeholder with the public key for the merchant that owns the checkout:

```tsx
import { SumUpProvider } from "@sumup/react-native-checkout";
import { PaymentScreen } from "./PaymentScreen";

type AppProps = { checkoutId: string };

export default function App({ checkoutId }: AppProps) {
  return (
    <SumUpProvider publicKey="sup_pk_YOUR_PUBLIC_KEY">
      <PaymentScreen checkoutId={checkoutId} />
    </SumUpProvider>
  );
}
```

Obtain a fresh `checkoutId` from your backend for the order being paid. Do not reuse a checkout from a completed order.

## Provide Payment Details

Create `PaymentScreen.tsx` with the following component. It initializes the sheet with the checkout ID from your server and enables the payment button only after initialization succeeds:

```tsx
import { useEffect, useState } from "react";
import { Alert, Button, View } from "react-native";
import { useSumUp } from "@sumup/react-native-checkout";

type PaymentScreenProps = { checkoutId: string };

export function PaymentScreen({ checkoutId }: PaymentScreenProps) {
  const { initPaymentSheet, presentPaymentSheet } = useSumUp();
  const [ready, setReady] = useState(false);
  const [presenting, setPresenting] = useState(false);

  useEffect(() => {
    let active = true;
    setReady(false);

    async function initialize() {
      try {
        const { error } = await initPaymentSheet({ checkoutId, language: "en" });
        if (!active) return;
        if (error) {
          Alert.alert("Could not prepare payment", error.status === "failure" ? error.message : "Cancelled");
          return;
        }
        setReady(true);
      } catch {
        if (active) Alert.alert("Could not prepare payment", "Please try again.");
      }
    }

    void initialize();
    return () => { active = false; };
  }, [checkoutId, initPaymentSheet]);

  async function pay() {
    setPresenting(true);
    try {
      const { error } = await presentPaymentSheet();
      if (error) {
        if (error.status === "failure") Alert.alert("Payment failed", error.message);
        return;
      }
      setReady(false);
      Alert.alert("Payment submitted", "Check your order status for confirmation.");
    } catch {
      Alert.alert("Payment result unavailable", "Check your order status before trying another payment.");
    } finally {
      setPresenting(false);
    }
  }

  return (
    <View>
      <Button title="Pay" disabled={!ready || presenting} onPress={pay} />
    </View>
  );
}
```

## Show Payment Sheet

Run the app, open your payment screen with a fresh sandbox checkout, and select **Pay**. Enter an [online test card](/online-payments/testing/) and complete any authentication challenge.

The sheet can complete, fail, or be cancelled. The example handles both returned SDK errors and rejected promises. Your backend must retrieve the checkout and verify its final status before marking the order paid. Follow [payment confirmation and order updates](/online-payments/guides/confirm-payment/) for server verification and notifications.

## Optional Integrations

### Save a Card for Future Usage

To save a card, create a customer and a checkout with `purpose: "SETUP_RECURRING_PAYMENT"` and that customer's `customer_id` on your server. Follow the [saved-card guide](/online-payments/guides/tokenization-with-payment-sdk/) for the backend flow and permission requirements.

Use `initSaveCardSheet` and `presentSaveCardSheet` from `useSumUp()` in a component under `SumUpProvider`:

```tsx
const { initSaveCardSheet, presentSaveCardSheet } = useSumUp();

async function saveCard(checkoutId: string, customerId: string) {
  const initialized = await initSaveCardSheet({ checkoutId, customerId, language: "en" });
  if (initialized.error) return;

  const result = await presentSaveCardSheet();
  if (result.error) return;
  // Ask your backend to retrieve the saved payment instrument for this customer.
}
```

Handle returned errors and rejected promises as in the payment example. Keep saved-card tokens and subsequent payment requests on your server.

### Use Google Pay

Enable Google Pay in your app's `AndroidManifest.xml`, inside `<application>`:

```xml
<meta-data
  android:name="com.google.android.gms.wallet.api.enabled"
  android:value="true" />
```

Pass the Google Pay option when initializing the sheet:

```tsx
await initPaymentSheet({
  checkoutId,
  language: "en",
  googlePay: { isProductionEnvironment: false },
});
```

Keep the test environment enabled while developing. Complete [Google's Android setup](https://developers.google.com/pay/api/android/guides/setup) before enabling production payments.

### Use Apple Pay

#### Register for an Apple Merchant ID

Register an Apple merchant identifier, configure your app's Apple Pay capability and certificates, and select that identifier in Xcode. Follow [Apple's Apple Pay setup](https://developer.apple.com/documentation/passkit/setting-up-apple-pay).

Pass the matching identifier when initializing the sheet:

```tsx
await initPaymentSheet({
  checkoutId,
  language: "en",
  applePay: { merchantIdentifier: "merchant.com.example.app" },
});
```

Test on a supported device with the merchant and wallet configuration you will use. Confirm the final checkout status on your server for wallet payments as well as card payments.
