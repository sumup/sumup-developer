A [user can have access to more than one merchant account](/tools/account/merchants-and-users/). Before making a request for a business, find the accounts available to the user and select the correct merchant code.

See [Run the examples](/tools/account/#run-the-examples) for shared setup.

## 1. Find the user's merchant accounts

For OAuth requests, the token needs `user.profile_readonly` or `user.profile`. An API key can also list accounts available to the identity it belongs to.

Call [List memberships](/api/memberships/list/) to find the accounts the user can access. Each returned item describes the user's access to one account.

Filter by `kind=merchant` and `status=accepted` to list merchant accounts the user has already joined. An invitation must be accepted before its account appears in this filtered list.

```bash
  --data-urlencode "kind=merchant" \
  --data-urlencode "status=accepted" \
  --data-urlencode "limit=25" \
  --data-urlencode "offset=0"
```

```go
package main

import (
	"context"
	"fmt"
	"log"
	"os"

	"github.com/sumup/sumup-go"

func main() {

	status := sumup.MembershipStatusAccepted
	limit, offset := 25, 0
	accounts, err := client.Memberships.List(context.Background(), sumup.MembershipsListParams{
		Kind:   &kind,
		Status: &status,
		Limit:  &limit,
		Offset: &offset,
	})
	if err != nil {
		log.Fatal(err)
	}
	fmt.Printf("%+v\n", accounts)
}
```

The API returns HTTP `200` with an `items` array and a `total_count`. Use these fields from each item:

| Field           | Use                                                   |
| --------------- | ----------------------------------------------------- |
| `resource.name` | Display the business name in an account picker.       |
| `resource.id`   | Use this merchant code for requests to that business. |

The examples request the first 25 results. If `total_count` is greater than the number retrieved, repeat the request with the same filters and increase `offset` by the number of items returned. Continue until you have retrieved all results.

## 2. Select an account

If there is one result, your application can select it automatically. If there are several, show the business names and let the user choose. Store the selected `resource.id` as the merchant code for that user's session.

If there are no results, the user has no accepted merchant accounts matching the filters. Check whether they still need to accept an invitation or sign in with a different user account.

Do not use an email address or a user ID as the merchant code. A business and the users who can access it are [separate](/tools/account/merchants-and-users/).

## 3. Use the selected merchant code

Pass the selected code wherever an endpoint asks for `merchant_code`, such as [List members](/api/members/list/) or [List readers](/api/readers/list/). Keep the selected account consistent across the data you display and the requests you make.

Choosing an account does not grant extra access. The user's [roles](/tools/account/roles/) and the token's [OAuth scopes](/tools/authorization/oauth/#authorization-scopes) still determine which actions are allowed.

When the user switches accounts, use the newly selected merchant code for subsequent requests and reload the displayed account data.
